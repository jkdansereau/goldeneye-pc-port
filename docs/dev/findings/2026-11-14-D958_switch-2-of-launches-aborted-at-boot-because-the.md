## D958: Switch: ~2 % of launches aborted at boot because the main thread's stack sat on the cart / DRAM windows — the N64 window base is now chosen at run time — IMPLEMENTED 2026-11-14 (Switch only; console-checked over 20+ launches, last round owed)

**Symptom.** About 2 % of launches logged `nxmem: 0x... is not free` and stopped at boot. The main thread's stack is placed at a random address in the process's stack region (1920 MiB) when the process is created, and the cart (`0x10000000`, 17.6 MB) and DRAM (`0x70000000`, 8 MB) windows were fixed there. An automatic relaunch is not an option: `appletRestartProgram` relaunches the *current application*, which from sphaira / hbmenu is the menu (it only restarts our NRO from a forwarder), and `envSetNextLoad` stays in the same process (same stack).

**Fix (port layer, `port/src/switch/nxmem.c`, `portaddr.h`).** `PORT_ADDR_BASE` is the variable `g_portAddrBase` on the Switch (`nxChooseAddrBase()`, called first in `portAddrInit`; the compile-time `-DPORT_ADDR_BASE` is no longer passed there). It picks a free 4 GiB-aligned slot in the ASLR region (slot 0 excluded so every launch takes the same code path; the search starts at a random slot and wraps). A slot is taken when the cart (128 MiB reserved), DRAM V1 and KSEG0, and the 512 MiB game-stack region are free, **outside the kernel's heap and alias regions** (`svcMapProcessCodeMemory` fails there with `rc=0xd401` although `svcQueryMemory` reports the pages unmapped; found on the console, slot 2), and not holding the executable. Without the own process handle (Ryujinx, a launch that is not hbloader) code memory is unavailable and the base stays 0 with the old stack-region mapping.

**What had baked the base in.**
- `port/src/dram_syms.S` (`cfb_16`, `_bssSegmentEnd`, `animations_frame_buffer`): now macros `PORT_DRAM_SYM` on the Switch (the file is not compiled there). Game-file edits, all `#if defined(PORT) && defined(__SWITCH__)` and ABI/layout class (an absolute link-time symbol replaced by a run-time lvalue, no logic change): `src/fr.h`, `src/bondgame.h`, `src/game/initanitable.c` (`D_80029D60`'s two buffer pointers are filled in `alloc_load_expand_ani_table` instead of a static initializer), `src/crash.c` (the PAL-only `g_StackPtrs2` entry for `cfb_16` is `NULL`; crash-dump lookup only).
- ROM labels (`romassets_*.s`): kept as link-time absolutes at their N64 value, they are only used as `u32` cart addresses. Direct reads through a label needed the base: `romdataCartPtr()` in `romdata.c` (`unknown2`, the RAW16 wavetable walks, `romdataFontPcSize`, `romdataAudioBankPcSize`).
- `portAddrIsMapped` compared against `CART_BASE` instead of the host cart address; `libultra.c`'s `static const` DRAM bounds became a plain local; `n64stubs.c` keeps the base-0 mempool ceiling (the preprocessor reads the variable as 0).

**The executable below 4 GiB (found by the launch series).** hbloader puts the NRO anywhere in the ASLR region, below 4 GiB in about one launch in seven. `seg_addr()` told a host pointer from a 32-bit N64 value by "at least 4 GiB"; a pointer into the image's own data (a static display list) then looked like an N64 address and got the window base added (`gfx_run_dl`, `far = base + 0x3ff94dc8`). The `gSP*` macros (`include/PR/gbi.h`, `GBI_W1`, PORT only; the N64 build keeps the plain cast) now store a **pointer-typed** argument with bit 62 set (`GBI_PTR_TAG`; an integer argument — segment address, `OS_K0_TO_PHYSICAL()`, `osVirtualToPhysical()` — is stored as is; the tag is an addend, so the `gs*` static forms stay link-time constants). `gfx_w1_is_host()` in `gfx_pc.cpp` reads a tagged value as a host pointer when it is at least 4 GiB or inside the image (`g_portImageEnd`, from `svcQueryMemory` at init); a tagged value elsewhere is an N64 address the game cast to a pointer type (`(Gfx *)u32`): the first version, which trusted the tag alone, crashed every launch on exactly such a value (`0x05002298`, segment 5). An untagged value is an N64 value (or a host pointer of at least 4 GiB, as before).

**Residual.** Only a tagged integer-cast-to-pointer N64 value that falls numerically inside an executable placed below 4 GiB is misread (a few launches in a thousand at most; none seen). Untagged values can never be taken for host pointers.

**Quit returns to the launcher (same entry, found while building the test loop).** `nxExitProcess` ends the whole application, so quitting from sphaira also took sphaira down and no test could follow another. The exit now stops everything of ours and returns from `exit()` to the loader (`portAtExit`, Switch only): `portThreadsStop()` sets `g_portQuit`, which the port's own blocking calls (`osRecvMesg`, `osSendMesg`, `osYieldThread`, the idle thread, the pacemaker, the render worker, the parked render thread) test, so the threads leave without touching game code; the threads are **joined** (libnx keeps a thread's stack mapped, as a mirror of the memory we gave it, until the thread is joined; the backing block cannot be unmapped before, `rc=0xd401`); audio closed, `SDL_Quit()`, mapped windows released. A thread that has not left after 4 s falls back to the old exit. The loader's abort on the return (`rc=0xd401`, Atmosphere report at `hbl+0x4034`, it unloads our image and heap) came from stacks still mapped: first the six game-thread stacks (never joined), then the pacemaker's (created detached, with the default stack: joinable now too). A memory-state dump taken just before the return (test build only, `nxDumpMemState`) is how they were found. The ~10 MB locked heap block that dump also shows is the loader's own buffer behind our image (its size is exactly the image extent), released by the loader itself: not a leak. An `nvExit()` loop tried along the way was checked useless (one launch without it, and the next upload, returned cleanly) and removed.

**Checked.** Console, via the nxlink stdio build (`docs/switch/nxlink-stdio.md`): 12 consecutive unattended launches (the test build quits itself after 10 s and the next upload follows), slots 1-12, one with the image below 4 GiB, boot to the menu, return to sphaira every time (the next upload always connected), no unmap error. Earlier series: slots 2-15, boot to the menu, options overlay. Ryujinx: base 0 path (no process handle). Owed: a full level on the final NRO, and the quit from a forwarder (not tried; it should land on Home).
