## D959: Switch crash when docking or undocking while the game runs -- SDL resizes the EGL surface on the host thread, under the render thread -- FIX BUILT 2026-11-14 (Switch only; console check owed)

**Symptom.** Toggling docked/handheld while the game runs crashed it (Ryujinx: `GuestBrokeExecutionException` out of `Fatal.IService.ThrowFatalWithCpuContext`, i.e. the game itself called `fatalThrow`; console: only system-module crash reports, see below).

**Evidence (three Atmosphere reports from the console).** `audio` (0100000000000014, result 0x265 = 2101-0001), `omm` (0100000000000045, 0x25A0B = 2011-0301) and `qlaunch` (0100000000001000, 0x25A0B), all `User Break` (a deliberate abort in the system module), timestamps 24 s and 25 s apart (audio first). No report names the game's own process, and no `ge007-crash.log` was written, so the game did not fault: it ended through the fatal service or was killed with the others. The system modules' frames cannot be symbolized here; they look like fallout of the application dying in the middle of the operation-mode change (omm is the operation mode manager). Confidence that the game's death is the first event: medium; that the three reports are only fallout: medium-low (a firmware / Atmosphere mismatch on the console is not excluded: test dock/undock from hbmenu alone).

**Root cause (from the libraries' disassembly, `libSDL2.a` `SDL_switchvideo.o`, `libEGL.a` `egl_switch.c.o`).** `SWITCH_PumpEvents` (run by every `SDL_PollEvent`, on whichever thread polls) compares `appletGetOperationMode()` with its cached value and on a change calls `SDL_SetWindowSize(1280x720 or 1920x1080)`; `SWITCH_SetWindowSize` then does `SDL_EGL_MakeCurrent(NULL)`, `SDL_EGL_DestroySurface`, `nwindowSetDimensions`, `SDL_EGL_CreateSurface`, `SDL_EGL_MakeCurrent(surface, SDL_GL_GetCurrentContext())`, all on the calling thread. The game polled SDL from two threads: the host main thread (`videoPumpEvents`, `video.c`, every 8 ms, the first to notice) and the render thread (`gfx_sdl_handle_events`). The host thread does not own the GL context (released after init), so the surface the render thread was drawing to was destroyed under it, and the new surface was made current with a NULL context. Mesa's Switch EGL driver calls `fatalThrow` when `nwindowQueueBuffer` fails in `switch_swap_buffers`, and in `switch_st_framebuffer_validate` (dequeue) and `switch_create_window_surface`. Confidence: high that this race exists and ends in `fatalThrow`; medium that it is the only crash on the console.

**Fix (port layer, Switch only).** The host thread no longer calls `SDL_PollEvent` on Switch (`video.c` `videoPumpEvents`, `VIDEO_HOST_POLL`); it calls `nxAppletAlive()` (`nxmem.c`: `appletMainLoop()`, quit request on applet exit, one log line on a mode change). The render thread polls at the start of a frame (`gfx_start_frame` -> `handle_events`), after the context is made current, so the resize runs on the context's thread between frames. The render pump gained `SDL_AUDIODEVICEREMOVED` (previously host only) and logs every `SIZE_CHANGED`. Dropped on Switch: the keyboard and wheel handling that lived only in the host pump (the options overlay opens from the pad).

**Console check (maintainer).** Dock and undock (a) in the front end, (b) in a level, (c) handheld -> docked and docked -> handheld, with MSAA and FXAA on and off. Send `ge007.log` lines `nxmem: operation mode ...` and `SDL: window size changed -> ...`; if it still dies, send `ge007.log` and any new crash reports (a `fatal_errors` file from Atmosphere would carry the `fatalThrow` result code).

**Open.** If it still crashes, the next suspects are the frame in flight when the surface is recreated (the FBOs are rebuilt on the size change in `gfx_start_frame`) and the Switch audio sink change at dock time.
