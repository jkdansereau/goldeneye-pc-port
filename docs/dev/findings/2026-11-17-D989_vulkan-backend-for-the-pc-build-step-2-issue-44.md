# D989

## D989: Vulkan backend for the PC build, step 2 (issue #44) -- drawing: SPIR-V combiner pack, uber-shader, textures, samplers, depth -- BUILT + RUN 2026-11-17 (Windows cross-build, RTX 5070: level 09 drawn like GL, validation 0 errors; maintainer play-tested)

**Change (port render layer only, no game code).**
- **SPIR-V pack** (`cmake/VulkanShaders.cmake`, `port/fast3d/gfx_vk_pack.S`): the deko3d pack's own pipeline with another compiler. Host `dkshgen glsl` writes the same GLSL from `port/switch/shaders/combiners.txt`; `glslangValidator -V --target-env vulkan1.3 --sub 4` compiles it and the hand-written `uber.*.glsl` unchanged, and `dkshgen pack` packs the SPIR-V in the `gfx_dk_layout.h` format. `--sub 4` moves the uniform blocks off the sampler bindings: textures 0 / 1, Draw 4, Comb 5, Mesh 6, all in descriptor set 0. The pack is `.incbin`'d by an assembler file in a library of its own (`ge_vkpack`, without the game's forced `versioninfo.h`). 136 combiners, 1.7 MiB. `Dockerfile.windows` gains `gcc-c++` (the host compiler for `dkshgen`).
- **Backend** (`gfx_vulkan.cpp`), mappings taken from `gfx_deko3d.cpp`: push descriptors (`VK_KHR_push_descriptor`, now required) for the two textures and the Draw / Comb uniforms (a fresh ring allocation whenever they change); pipelines made on first use, keyed on program x blend (off / alpha / modulate) x colour writes x samples x alpha-to-coverage x attachment formats; viewport, scissor, depth test / write / compare, depth bias and culling dynamic (1.3 core). The uber-shader reads every attribute location: the ones a combiner lacks come from a 256-byte zero buffer bound with stride 0. A combiner missing from the pack is drawn by the uber-shader and logged once (`SPIR-V miss`).
- **Orientation and depth:** as deko3d, every target is stored top-down; the viewport has a negative height (NDC +y up and GL's winding kept), and GL's bottom-up viewport / scissor / clear rectangles are mirrored (y' = H - y - h). With `VK_EXT_depth_clip_control` the clip z stays GL's -1..1; without it `get_clip_parameters` asks `gfx_pc.cpp` for 0..1 z (the mesh path will need the extension). Depth clamp on when the device has it; decals use depth bias (-2, -2) as GL's `glPolygonOffset`. Window depth: D24S8, else X8_D24, else D32F.
- **Memory and frames:** host ring (`DkRing`, 8 MiB host-visible coherent chunks: vertices, uniforms, upload staging; `stream_begin` hands out ring memory as deko3d does) and first-fit image heap (`DkHeap`, 64 MiB device-local chunks per memory type), both from `gfx_dk_heap.h` and recycled by submission serial; dead images and pipelines wait for their serial too. Each frame records uploads in a "pre" command buffer (every upload is a fresh image, so it may run ahead of the frame's draws) and rendering in the main one; one `vkQueueSubmit2` per frame, the swapchain image acquired at the first draw or clear that reaches the window.
- **Textures and samplers:** RGBA8 images, the CPU box mip chain of deko3d when mipmaps are wanted (or three-point / trilinear); samplers cached by GL's sampler key (non-mipmapped minification = `maxLod 0.25`; mirror-clamp falls back to mirrored repeat without `samplerMirrorClampToEdge`, as GL does).
- `shaderDemoteToHelperInvocation` is enabled: glslang compiles `discard` to `OpDemoteToHelperInvocation` for SPIR-V 1.6 (the validation layer flagged it).
- Off-screen framebuffers are step 3: `vk_init` sets `gfx_framebuffers_enabled = false` (GL's path when the driver has no FBOs), so FXAA, MSAA and framebuffer effects are off under Vulkan for now. `video.c`: `s_vulkanActive` is defined in every build (the step 1 exit-log change broke the Switch build).

**Verified.** Windows cross-build, `GE_RENDERER=vk -level_09` on an RTX 5070 with the MSYS2 validation layer (D988): the level, gun and HUD are drawn like GL's capture of the same intro (textures, depth, alpha, orientation); 0 validation errors; no `SPIR-V miss`; 34 pipelines; clean exit. The maintainer played the build. Linux and Switch build.
